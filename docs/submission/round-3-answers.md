Two connector facts worth stating plainly, both verified live:

- Connector names must begin with a native registry name: `POST /api/v1/connectors` answers
  `422 {"detail":"Unknown native connector. Use '<native_connector_name>_<your_suffix>'"}`. `vachana_*` is rejected;
  the registry contains `mcp`, so ours are `mcp_*`.
- A connector caches the tool schema it discovered at registration. Changing a tool signature requires registering a
  **new** connector record — which is why the name runs `_v21` … `_v24`.

**Changed after this round:** an explicit ordered rule — every losing or abandoned bid releases its mandate *in the
same run*, and nothing is claimed without the call that did it. Landing it exposed a platform constraint: a prompt is
locked on an active agent (`409 Prompt is locked on active agents`). A clone (v5) was built to carry the rule and
**never reached promotion** — 0.616 accuracy over 44 samples. The rule finally landed when we found that a **paused**
agent's prompt is editable: pause → `PATCH system_prompt_text` → resume. Every prompt fix since has used that cycle.

L12 re-run after the fix: 409 → `release` → `RELEASED 120000`. L07 re-run: the agent now calls `release`, and when
the argument arrived null it said "There was an issue with canceling the reservation hold" — honest, which is the
property that matters.

#### Round 4 — 2026-10-03, the v6 rewrite and the full L01–L10 sweep

v6 was not triggered by a correctness failure but by a scoring one: v4 sat at 69.1% over 310 samples against an 80%
floor. We measured the platform's per-turn confidence across all 377 turns and found it mechanical, not a judgement —
0.85 once any tool has been attempted in the thread, otherwise 0.60 for a reply ≤100 characters and 0.65 for ≥101,
boundary exact. v4 asked one field per turn and only touched a tool after the final yes, so half its turns scored
0.60 by construction. Reaching 80% would have needed 676 more turns at 0.85.

**Changed in the prompt:** look the release up as soon as one unambiguous event is named; ask missing fields
together in one question; always carry the reserve total in the read-back; read an unstated minimum back as "all or
nothing unless you tell me a smaller group would do"; run money tools one at a time; undo a pool entry with the newly
granted `cancel_declaration` before releasing; claim nothing without the tool call that did it.

**Levers we rejected on purpose:** padding replies past 100 characters, calling a tool only to trigger the 0.85
bucket, and filler samples. All three would have raised the number without improving the agent.

Eight more defects were found on a shadow twin before promotion, including: "all or nothing" being parsed as an
ambiguous price because it contains the word "or"; `declare_interest` firing in parallel with `create_mandate`; wrong
weekday arithmetic ("Wednesday, 11 October"); a spurious "this bid cannot win" warning when the ceiling was *above*
the cheapest slot; and an over-fitted Hinglish example copied verbatim into English conversations.

Result: **L01–L10 all pass**, with two honest caveats — L03 passed on logic but still replied in English to Hinglish,
and L09's pool held one entry but the second declaration overwrote the first bid's mandate (a mock defect, fixed the
same day by keying the fallback declaration id on the mandate id too, which required registering a new connector

test so far injected synthesized speech directly into the room — so the recording is itself that test. A caller's

another on a guess. And Gnani's TTS has returned four consecutive 500s in production: the reply was in the transcript

trouble speaking right now. Your words are still being heard."
